# 初始化与目录地图

## 发现并复用项目资料

确认目标仓库根目录及适用规则，检查已有管理资料、README、需求设计文档、构建清单、测试/CI 和代码入口。仓库当前未提交的修改属于现有工作；读取 Git 状态了解范围，不重置文件。

已有 `.project/` 时增量补齐并维护。已有等价 PRD、接口文档或任务系统时在 INDEX.md 引用，避免另建一套相互矛盾的资料；用户明确要求迁移时再整理。不要将引导模板写入 skill 安装目录。

初始化的核心输出是 INDEX.md、PROJECT.md、BACKLOG.md、STATE.md 和真实模块的 MAP.md / CONTEXT.md。任务与集中工作计划按实际请求建立，分工直接记录在任务中。尚无任务证据时 STATE.md 记录初始调查状态，不虚构完成数。

使用 [backlog.md](../assets/templates/backlog.md) 创建可由用户手写的需求收集箱，维护规则见 [backlog.md](backlog.md)。已有用户清单时保留并引用，或按已授权范围整理；不要把整个 PRD、已有实现或智能体建议都导入成用户的新需求。没有用户输入时保留空清单，不填入虚构想法。

## 建立地图

1. 用 `rg --files --hidden` 或等价工具列出文件，结合版本控制忽略规则确定范围。显式说明依赖缓存、Git 内部文件、构建产物、运行数据及敏感文件的排除项；保留需要管理的源码、测试、配置模板、脚本和文档。
2. 从构建清单、入口和代码关系识别模块边界。默认覆盖整个项目；大型仓库分批处理，记录各批范围及尚未完成的目录，不把部分扫描标成完整地图。
3. 读取纳入范围的文本文件内容，为每个文件写一句具体职责说明。相似文件可以批量阅读，但不根据扩展名、名称或所在目录直接猜测。二进制文件记录资源类别和已知用途，无法核实则说明。
4. 用 tree 字符展示真实层级，并在每个文件后以 `#` 写职责注解。现存文件和拟新增文件分开；拟新增文件只写在任务/方案中。
5. 为模块写 CONTEXT.md：主要职责、入口、关键调用/数据流、上下游、开发验证方式、已知问题。区分静态代码观察和已运行验证，记录证据路径。
6. INDEX.md 只展示模块总览和地图链接。某个模块太大时使用 `modules/{module}/{submodule}/MAP.md`，父地图保留目录节点及子地图链接，各文件由一张地图负责。

参考 [index.md](../assets/templates/index.md)、[project.md](../assets/templates/project.md)、[map.md](../assets/templates/map.md)、[context.md](../assets/templates/context.md)、[state.md](../assets/templates/state.md)。复制后以调查结果填写，替换模板提示。

## 更新地图

以 Git 的新增、删除、重命名和修改定位受影响文件。比较原有职责与当前内容，只更新受影响分支；功能改变但路径未变也可能需要修订注解。无 Git 时比较现有地图与真实文件清单。

移动文件后检查任务、模块文档和接口约定中的旧路径引用。删除文件的历史证据保留，并注明它对应的旧提交；不修改历史记录来伪装当前路径一直存在。

每张地图记录更新时间、覆盖根目录、核实范围、提交（可获取时）和省略规则。目录树默认相对于仓库根目录，用精确路径引用代码，不绑定用户机器的绝对路径。

## 初始化结论

从文档和代码梳理当前能力，将已观察实现、待验证、缺失和未调查明确区分。优先级依据用户目标及依赖关系；没有负责人、期限或预算时标记待确认。只有缺失信息阻止正确选定仓库或工作范围时才询问，不为填写每个字段逐项提问。

创建后检查地图路径存在、链接可达、没有职责重复覆盖或遗漏的未说明范围，并向用户交付入口及调查结论。
