# 需求与灵感收集箱

## 目的与入口

`.project/BACKLOG.md` 是用户可以手动持续追加的清单。使用 [backlog.md](../assets/templates/backlog.md) 创建，建立 INDEX 导航链接。用户只要求记录想法时可以仅创建或更新收集箱，不触发全仓扫描和完整初始化。

用户可以在“随手记录”追加普通列表项、一句话或多行描述，也可以直接修改已有条目；不要求先提供 ID、优先级或负责人。智能体接手时识别未整理输入，处理与本次请求有关的部分。

## 记录和整理

- 用户说“记下来/加个需求”时忠实追加，默认待整理。只记录不扩展成方案、任务、排期或实际开发。
- 用户说“整理清单”时保留原意，为条目补稳定 ID、简短标题和分类，查找相近条目；评估建议与用户原文分开写。
- 原始输入可以保持在随手区，也可以完整移入已整理条目的“原始想法”中；整理后不要在两个位置形成两份可分别维护的原文。移动时保留全部细节，注明来自手写条目。无法确定原始日期则写“未记录”，不将整理日期冒充提出日期。
- 不同想法拆分时记录共同出处。发现疑似重复时链接相关条目并说明差异，不自动删除或合并；明确重复且用户要求去重时合并并保留旧 ID/来源引用。
- 用户手改已纳入条目时，将新描述与关联任务/计划比较；发现差异就指出待同步范围，未经规划请求不直接改动已约定的工作安排。
- 不重写无关条目，不清空手写区覆盖新输入。保存前检查是否出现其他参与者的新修改，必要时合并或由维护者协调。大清单按功能拆到 `backlog/{topic}.md`，主 BACKLOG 保留入口与随手区，条目保持唯一出处。

## 已整理条目格式

下面是格式示例；创建空清单时不要把示例当成用户需求写入。

```markdown
### IDEA-8c9c4d2e｜支持导出聊天记录

- 状态：待整理
- 提出时间：未记录
- 整理时间：实际日期
- 来源：用户手写 / 当前请求 / 指向原始资料的链接
- 关联：无

**原始想法**
保留用户原文，包括尚不完整的描述。

**整理与评估**
有明确整理请求时填写理解、价值、影响范围和待确认问题；没有评估则写“尚未评估”。
```

复用已有 ID。新 ID 使用项目既有规则，或使用 `IDEA-` 加随机后缀并检查唯一性，避免多人同时取同一递增编号。标题和顺序改变不修改 ID。链接条目时使用生成后的实际 Markdown 锚点并检查；无法可靠生成锚点时链接文件并在标签注明 ID。

## 收集箱状态

| 状态 | 含义 |
| --- | --- |
| 待整理 | 原始想法已记录，尚未评估 |
| 待确认 | 已有初步理解，但关键范围或决策不明确 |
| 已纳入 | 已授权安排具体工作，存在可追溯的任务/计划链接 |
| 暂缓 | 明确留待以后，保留理由或再考虑条件 |
| 不采纳 | 明确决定不做，保留决策来源与理由 |

评估后的优先级和采纳意见默认是建议。以用户当前请求、既有授权或团队已确认决策为依据更新采纳状态；不能把“写进清单”“很有价值”当作纳入本期的决定。未知决策保持待确认，不催促逐条审批。

## 转成正式工作

用户要求规划、安排工作或实现选定条目时，读取相关 PROJECT/模块资料，按 [planning.md](planning.md) 建立或更新任务，必要时补集中计划。记录原条目 ID 作为来源，再回链文档；若本次仅记录“决定纳入”但未形成任务或计划，注明情况并保持待确认，待工作具体化后标记已纳入。

想法影响既有工作时复用关联计划，新增或调整相关任务，不机械地为每个条目创建独立功能目录。纳入状态与开发状态分开；任务全部完成也不把收集箱状态改成“已完成”，通过任务链接查看执行进度。

完成记录操作后链接 BACKLOG，说明新增/整理条目以及实际采纳变化。没有创建任务或执行代码时不声称已开始开发。
