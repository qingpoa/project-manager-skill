# 用户需求清单

## 新增边界

`.project/BACKLOG.md` 只收录用户明确要求“添加到清单”“记下这个需求”等表达，或用户亲手写入的需求。普通功能反馈、要求修改代码、项目盘点和智能体建议都不自动产生清单条目。

初始化使用 [backlog.md](../assets/templates/backlog.md) 保留空清单，不放示例需求。智能体发现的问题记录在 STATE 或相关 TASK；只有用户明确要求将其中某项加入清单时，才新增条目。

## 显示形式

每条只写简短需求与完成复选框：

```markdown
- [ ] 支持导出聊天记录
- [x] 编辑伴侣资料后直接保存
```

以上仅是格式示例，不写入空清单。省略日期、来源、分析、处理状态、负责人、任务链接和验证细节。必要的原始请求、详细约束、实现过程和检查依据放在 TASK/records，按 [planning.md](planning.md) 维护。

用户可以自己追加短句；用户要求整理时转换为复选框并保留意思，不新增、拆分、合并或删除用户没有要求变动的需求。已有用于任务追溯的 ID 可以保留为同一行的 HTML 注释，不强制用户填写或展示编号。

## 完成勾选

新增默认 `- [ ]`；用户需求整体完成，且关联任务/实际检查支持结论时改为 `- [x]`。一个需求拆成多个任务时，相关工作全部完成才勾选。开发中、阻塞、暂停或取消保持未勾选，具体原因留在任务中。

用户明确设置的勾选状态优先保留；有实际证据与之冲突时说明差异，未经请求不凭猜测重写。完成勾选可以根据已登记需求的工作结果维护，但不借此向清单导入新需求。

修改已有复杂清单时只精简显示，保留需求本身和完成情况。原始请求及必要关联转存到相关任务，已有 ID 不失效；没有任务可承接且内容必须保存时先说明范围，不静默丢弃用户信息。

## 操作结果

用户要求添加时追加一条短句并链接 BACKLOG；用户要求查看时展示需求与完成状态。添加需求只表示登记，不自动执行开发。清单之外的任务仍然可以正常创建和推进。
