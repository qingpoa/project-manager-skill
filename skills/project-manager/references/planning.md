# 工作计划与任务拆解

## 输入与输出

从 PROJECT、BACKLOG、已有设计和涉及模块的 CONTEXT 开始，复用已有任务。仅盘点已有工作时不要主动扩张产品范围。使用 [task.md](../assets/templates/task.md) 建立独立任务；涉及多个任务、需要集中说明方案时使用 [plan.md](../assets/templates/plan.md)。简单工作只建立任务，不额外创建功能目录。

从用户需求清单安排工作时遵循 [backlog.md](backlog.md)：用户明确要求添加时才在 BACKLOG 追加简短复选框；要求拆解或实现时建立任务，必要时补集中计划。范围歧义和实现分析写在任务/计划中。用户提出开发要求但未要求加入清单时，可以直接建任务，不自动添加 BACKLOG 条目。

PLAN 描述方案、跨模块协作、任务引用和实施顺序。TASK 直接记录要做什么、涉及哪些文件、当前做到哪一步和实际检查结果。每个可独立执行和核实的工作单元形成一份 TASK，不机械地将代码、测试和文档拆成无法独立交付的小任务。

## 标识与字段

任务元信息使用以下字段：

| 字段 | 含义 |
| --- | --- |
| id / title | 稳定唯一 ID / 简短任务名称 |
| feature / modules | 工作分组标识 / 涉及模块列表；未知分组可为 null |
| owner / assignee / reviewer | 交付负责人 / 当前执行者 / 已有安排中的评审者；未知为 null |
| status | 生命周期状态，见 verification.md |
| priority | p0 / p1 / p2 / p3，未决定为 null；正文说明理由 |
| depends_on | 前置任务 ID 列表，仅表达阻塞依赖 |
| write_scope | 预计修改的仓库相对路径或目录；是协作声明，不是锁 |
| source | 原始想法 ID、已有文档或用户请求出处，未知为 null |
| updated_at | 实际更新时间，ISO 格式字符串 |
| verification | 状态、核实时间、核实版本；具体依据在正文 |

复用已有 ID。串行创建可沿用项目编号；并行创建使用随机后缀，例如 CHAT-8c9c4d2e，并检查唯一性。标题、顺序或归档变化不修改 ID。替换模板中的 TASK-ID。

代码路径相对于仓库根目录；Markdown 导航链接相对于当前文档。YAML 日期时间加引号，空列表用 []，未知值用 null。

## 任务内容

写明目标及来源、工作范围、必要接口输入输出、依赖、当前结果、检查依据、阻塞和下一步，让未参与讨论的执行者也能接手。共享资料用链接引用，不复制整篇。

跨模块接口需要集中维护时使用 [contract.md](../assets/templates/contract.md)，说明请求/响应、错误、兼容性和负责模块。方案选择和影响直接写在计划或任务正文。

## 依赖与优先级

- 检查依赖指向存在任务、无自依赖、无环。同属一个功能不自动意味着互相阻塞。
- 跨仓库依赖说明外部出处和核实情况，不伪造本地任务 ID。
- 前置任务取消不自动解除依赖，要检查替代工作和下游影响。
- 通过依赖和 write_scope 识别可并行工作与重叠修改；不同文件仍可能存在接口或数据迁移冲突。
- 依据用户目标、阻塞影响和风险排序，不擅自决定日期、人员产能或精确工时。

用户问下一步时给出当前可执行任务及理由，明确被阻塞任务的前提。

## 变更与关联

保留已完成任务及检查记录。新想法影响工作范围时检查关联计划、任务和接口，说明变化。额外工作通常新建后续任务；实际回归可重开原任务并记录原因。

任务 source 引用已登记的 BACKLOG 条目（复用已有 ID 或填写需求短句）。任务负责保存原始请求、实现和检查细节；BACKLOG 只维护完成勾选，不回填计划或验证说明。用户需求整体完成后才勾选；拆成多个任务时检查相关任务是否全部完成。

交付前检查所选想法与任务的对应、依赖和修改重叠；指出未分配及待确认事项。执行授权明确时继续实际工作，否则交付规划资料与建议。
