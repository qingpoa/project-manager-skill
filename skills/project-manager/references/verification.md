# 进度核实与汇总

> **硬红线**：① 区分静态观察、替身/Mock 测试与真实运行验收；② `STATE.md`/`MAP.md`/`CONTEXT.md` 按主题原地替换，不在顶部堆叠日期流水账；③ 盘点或刷新先运行 `scripts/check_project.py` 做机械核对；④ 绝不借汇总或盘点擅自向 `BACKLOG.md` 新增需求。

## 状态含义

| status | 含义 |
| --- | --- |
| unknown | 导入或首次调查，状态尚未确定 |
| planned | 已记录工作，范围或前置条件仍需明确 |
| ready | 目标和范围明确，前置依赖已满足，可认领 |
| in_progress | 有执行者正在开展工作 |
| blocked | 障碍阻止当前工作，记录原因和解除条件 |
| in_review | 结果已交付，项目已有安排中的评审尚未结束 |
| done | 任务目标已完成，相关检查支持完成结论，已有的必要评审已结束 |
| cancelled | 已明确取消，保留原因并检查下游依赖 |

verification.status 独立使用 not_run / passed / partial / failed / stale / unavailable。任务状态不由文件数量、提交数量或勾选比例直接推导。

## 核实过程

根据用户要求选择模块、工作计划或任务范围，检查摘要时间与证据版本，读取任务目标、当前代码和相关变更。只运行当前问题需要的检查；进度查询不自动执行发布、生产写入、计费或通知。

区分静态观察、运行检查、人工评审/用户确认，以及推断/待确认。文件存在、Mock 演示、执行者报告都不足以证明真实功能已完成。lint 不能代替构建或业务行为检查；环境不可用时记录 unavailable 及原因。

检查依据记录实际时间、来源、代码版本/未提交范围、方法、结果和覆盖范围。相关代码或接口变化后旧证据可能 stale，说明需复验的范围。历史 done 不因本次未运行自动变成未完成；发现实际回归或此前结论不成立时说明原因并重开或建缺陷任务。

使用 [task.md](../assets/templates/task.md) 和 [record.md](../assets/templates/record.md) 保存实际结果，不增加独立标准文档或强制检查清单，不为盘点运行所有无关测试。

## 刷新当前资料

用户要求刷新、精简或检查过期信息时，以所选范围现状为目标，按以下过程完成；日常任务结束时对受影响部分使用同样原则。

1. 读取现有摘要、相关任务和当前代码/文档依据，区分当前事实、过去交付、仍存差距及未核实事项。保留用户已有修改，不能用模板覆盖整个项目或抹掉尚存问题。
2. 逐项处理旧结论：仍成立的保留；已变化的替换；已解决问题移出当前阻塞；已撤销方案移出当前流程；只在对应 TASK/records 保留历史。未知的运行版本、数据量、配置状态不再沿用旧快照。
3. 收敛重复来源：完整检查过程和输出留 records，TASK 保留当前结果与链接；STATE 引用最近一次相关检查及其实际时间/范围；CONTEXT 保留现行职责、调用关系、开发约定、仍存边界、配置键和可运行命令。INDEX 不复制测试流水、任务全历史或数据快照。
4. 完成相关一致性核对：任务状态统计与 TASK 一致；地图声明数量/路径与实际文件一致；旧接口和已修复差距不再混作当前事实；更新改动文档的核实时间与范围。本轮只检查目录就说明目录检查，不宣称逐项功能已验证。
5. 检查本地链接。历史截图/复验脚本已不存在时标明附件缺失，保留当时发生过的检查，不把失效链接或无法重看的截图充当当前证据。旧流程若仍有历史价值，标注交付时点并链接现行来源。

刷新不以内容变长为目标，也不要求删除所有旧日期。不要机械删减真实约束、用户原始请求和仍有价值的证据，不为每次刷新新增清理任务、日志文件或归档副本。只有整理确实需要或用户要求时才建立备份/归档。

例如：代码已经提供候选审批接口时，应移除当前“缺少审批接口”的旧结论并更新现状；不能另加一段“后续已实现”却继续把它留在未完成列表中。

## 汇总 STATE

使用 [state.md](../assets/templates/state.md)，先运行 `scripts/check_project.py --root <仓库根目录>` 取得任务统计、断链与地图差异，再读取所选范围的 TASK 汇总，不仅转抄上一版状态并更新日期。

摘要包含当前重点、汇总时间与范围、实际任务统计、仍存阻塞和下一步。若工作区长期存在多批未提交改动，在 `### 当前未提交改动主题` 按主题原地归纳，提交后清空；被后续未提交改动触及的旧检查结果在检查表里显式标注 `stale`（待复验）。检查结果注明各自的检查时间、来源任务/记录和范围；本次未运行的历史结果不能写成“本次已运行”。部分核实时明确未覆盖范围，旧测试数不逐条复制。

取消项和尚未建立任务的已要求工作单列。可以显示已完成 N / 纳入范围 M 项任务，但不称其为整体产品完成度，也不用等权比例预测交付日期。

检查依赖任务缺失、分工冲突、摘要陈旧和地图路径失效等一致性问题；在授权范围内修复可确定的错误，不确定的保留待确认。

已登记的用户需求完成后，按 [backlog.md](backlog.md) 更新对应复选框。尚未完成、阻塞或取消均保持未勾选；不得为了汇总进度自行新增需求条目。

## 工作结束与历史

保留实际结果、检查依据和未解决事项，保持任务路径稳定。当 `tasks/` 下已完结任务达到归档阈值（默认 25 项）时，在交付摘要中提示用户是否按功能或阶段归档到 `archive/`；仅在用户要求整理历史时创建快照或归档并检查链接，不移动仍被引用或阻塞活跃工作的任务，不删除历史记录。

交付核实结论和范围限制，链接入口与关键任务。静态盘点、格式验证和真实运行检查分别说明。
