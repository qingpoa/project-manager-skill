# 进度核实与汇总

## 状态含义

| status | 含义 |
| --- | --- |
| unknown | 导入或首次调查，状态尚未确定 |
| planned | 已记录工作，范围或前置条件仍需明确 |
| ready | 目标和范围明确，前置依赖已满足，可认领 |
| in_progress | 有执行者正在开展工作 |
| blocked | 障碍阻止当前工作，记录原因和解除条件 |
| in_review | 结果已交付，项目已有安排中的评审尚未结束 |
| done | 任务目标已完成，相关检查支持完成结论，已有的必要评审已结束 |
| cancelled | 已明确取消，保留原因并检查下游依赖 |

verification.status 独立使用 not_run / passed / partial / failed / stale / unavailable。任务状态不由文件数量、提交数量或勾选比例直接推导。

## 核实过程

根据用户要求选择模块、工作计划或任务范围，检查摘要时间与证据版本，读取任务目标、当前代码和相关变更。只运行当前问题需要的检查；进度查询不自动执行发布、生产写入、计费或通知。

区分静态观察、运行检查、人工评审/用户确认，以及推断/待确认。文件存在、Mock 演示、执行者报告都不足以证明真实功能已完成。lint 不能代替构建或业务行为检查；环境不可用时记录 unavailable 及原因。

检查依据记录实际时间、来源、代码版本/未提交范围、方法、结果和覆盖范围。相关代码或接口变化后旧证据可能 stale，说明需复验的范围。历史 done 不因本次未运行自动变成未完成；发现实际回归或此前结论不成立时说明原因并重开或建缺陷任务。

使用 [task.md](../assets/templates/task.md) 和 [record.md](../assets/templates/record.md) 保存实际结果，不增加独立标准文档或强制检查清单，不为盘点运行所有无关测试。

## 汇总 STATE

使用 [state.md](../assets/templates/state.md)，读取所选范围的 TASK 后汇总，不仅转抄上一版状态并更新日期。

摘要包括汇总时间、任务和证据范围、各状态数量、活跃任务/执行者、阻塞及影响、未分配工作、待确认事项、下一步和链接。部分核实时明确未覆盖范围。

取消项和尚未建立任务的已要求工作单列。可以显示已完成 N / 纳入范围 M 项任务，但不称其为整体产品完成度，也不用等权比例预测交付日期。

检查依赖任务缺失、分工冲突、摘要陈旧和地图路径失效等一致性问题；在授权范围内修复可确定的错误，不确定的保留待确认。

已登记的用户需求完成后，按 [backlog.md](backlog.md) 更新对应复选框。尚未完成、阻塞或取消均保持未勾选；不得为了汇总进度自行新增需求条目。

## 工作结束与历史

保留实际结果、检查依据和未解决事项，保持任务路径稳定。仅在用户要求整理历史时创建快照或归档并检查链接，不移动仍被引用或阻塞活跃工作的任务，不删除历史记录。

交付核实结论和范围限制，链接入口与关键任务。静态盘点、格式验证和真实运行检查分别说明。
