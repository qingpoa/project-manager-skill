# 编码与架构规范

> 说明：本文件为**可选配置**，仅在用户要求制定、沉淀或更新当前项目的代码与架构规范时建立。按主题原地维护，不在顶部堆叠日期流水。
> 编写原则：只写**本仓库可执行、可审查、能防跑偏**的具体约定（架构边界、扩展接口、禁用的反模式、安全/兼容红线、必需检查）；不抄通用语言常识（如“命名要有意义”），不重复已有 linter/formatter 默认规则。

## 架构分层与边界

- 明确模块分层、单向依赖与禁止越权跨层调用的边界（如路由层 vs 编排层、前端 UI vs 本地服务/存储）。

## 扩展与复用约定

- 说明新增功能应接入的现有注册表、预留接口、适配器或插件规范，避免通过修改核心分支硬编码堆砌能力。

## 代码风格、命名与类型

- 仅补充项目特有的命名、样式覆盖、公共类型真源与工具链未强制到的约定；与 linter/CI 配置文件保持一致。

## 数据、安全与兼容性红线

- 说明密钥存储与脱敏边界、表结构迁移/备份兼容要求、外部协议兼容性及禁止删改的运行/资产目录。

## 测试与交付门槛

- 列出修改不同层级代码后必跑的检查命令（静态检查、单测、构建），并区分自动化/替身测试与真实环境验收边界。

## 明确禁止的反模式

- 列出历史上容易回流或明确禁止的写法（每条给出具体替代方案）。
