# 项目规则与资料轻量同步

- **编码与架构规范**：若项目存在 `.project/CONVENTIONS.md`，动手改代码或重构前先读取并遵守其中约束；若经用户确认演进了稳定架构规范，原地同步更新该文件（未启用 `.project/CONVENTIONS.md` 时忽略本条）。

完成代码修改后、交付前，根据本次实际变更定点检查 `.project/` 中受影响的资料：

- 行为、配置、接口或数据边界改变时，更新相关模块的 `CONTEXT.md`；文件新增、删除、移动或职责改变时，更新相关 `MAP.md`。
- 存在新的验证结果、失败或待复验事项时，更新 `.project/STATE.md`，注明时间、检查范围及代码版本或未提交状态；未提交改动触及既有行为时将受影响的旧检查标为待复验（`stale`），不把旧结果当作新实现的验收。
- **原地替换，不堆流水**：更新 `STATE.md`、`CONTEXT.md`、`MAP.md` 时原地修改对应章节，不在文件顶部按日期追加更新日志；有未提交改动时在 `STATE.md` 原地维护「当前未提交改动主题」。
- 先读取再定点修改，保留已有资料与其他人的工作；无相关变化无需写入，不为普通小改新建任务或重做全项目盘点。新建任务前先确认编号唯一且目录名与 YAML `id` 一致（可用 `project-manager` 自带的 `scripts/check_project.py` 校验一致性或获取 `--next-id`）。
- `.project/BACKLOG.md` 只收录用户明确要求加入清单的需求。不要写入凭据、私人对话或实际用户数据。

如果 `.project/` 当前被 Git 忽略，说明它不会随普通提交自动同步；不要擅自更改这一策略。
